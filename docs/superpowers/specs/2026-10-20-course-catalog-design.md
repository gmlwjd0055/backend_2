# 강의 카탈로그 및 상세 조회 설계

## 목표

현재 노트 게시판 중심의 프론트엔드를 온라인 강의 카탈로그로 전환한다. 방문자는 판매 중인 강의를 목록에서 둘러보고, 강의 상세에서 강사와 강의 소개 및 가격을 확인할 수 있다. 강사는 한 명이며 기존 사용자들은 수강생으로 취급한다.

이번 범위는 상품 정보의 조회 경험까지다. 강사용 강의 등록/수정 화면과 API, 수강 신청, 결제, 강의 재생은 구현하지 않는다. 화면을 확인할 수 있도록 초기 데모 강의를 DB에 멱등하게 준비한다.

## 사용자 흐름

1. 사용자가 `/`에서 강의 목록을 본다.
2. 목록은 강의 제목, 짧은 소개, 카테고리, 대표 이미지, 강사명, 가격을 보여준다.
3. 사용자는 강의를 선택해 `/courses/{id}`로 이동한다.
4. 상세 화면에서 전체 소개, 강사, 분류, 난이도, 총 학습 시간, 가격을 확인하고 목록으로 돌아갈 수 있다.
5. 데이터 로딩 중에는 진행 상태를, 목록이 비었을 때는 빈 상태를, 조회 실패 시에는 오류 및 재시도 동작을 보여준다.

결제하지 않는 동작을 구매 버튼처럼 표현하지 않는다. 결제 시스템 추가 전까지 상세 화면에는 가격을 정보로 표시한다.

## API 계약

기존 FastAPI 응답 봉투 `{ code, message, result }`를 유지한다.

### `GET /courses`

- 인증 없이 공개한다.
- 응답 `result`는 강의 배열이다.
- 배열 원소 필드: `id`, `title`, `summary`, `category`, `thumbnail_url`, `instructor_name`, `price_krw`, `level`, `duration_minutes`.
- 기본 정렬은 최신 등록 순으로 한다.
- 이 단계에서는 페이지네이션, 검색 및 카테고리 필터 파라미터를 API에 추가하지 않는다. 프론트엔드에서 조회한 목록을 검색/분류할 수 있다.

### `GET /courses/{course_id}`

- 인증 없이 공개한다.
- 응답 `result`는 목록 필드에 `description`을 더한 강의 객체다.
- 존재하지 않는 ID는 HTTP 404 및 기존 오류 봉투를 반환한다.

## 데이터 모델 및 초기 데이터

SQLAlchemy `Course` 모델을 추가한다. `id`는 정수 기본 키, `price_krw`와 `duration_minutes`는 음수가 아닌 정수로 제한한다. `title`, `summary`, `description`, `category`, `instructor_name`, `level`은 문자열이며 `thumbnail_url`은 로컬 경로 또는 전체 URL을 보관한다.

초기 데모 데이터는 한 명의 강사 이름을 모든 강의에서 일관되게 사용한다. 시드 작업은 이미 존재하는 강의를 중복 삽입하지 않으며, 기존 DB의 다른 테이블과 데이터는 변경하지 않는다. DB 테이블 생성 및 시드는 현재 SQLAlchemy `Base.metadata.create_all` 초기화 방식과 충돌하지 않게 연결한다.

초기 목록에는 다음 강의 세 개를 등록한다. 가격과 소개는 데모 콘텐츠이며 운영자가 이후 강사용 등록 기능을 추가할 때 수정할 수 있다. 강사명을 제공받지 않았으므로 세 강의 모두 `강사`로 표시한다.

| 강의명 | 카테고리 | 가격 | 난이도 | 학습 시간 |
| --- | --- | ---: | --- | ---: |
| FastAPI로 만드는 첫 백엔드 API | 백엔드 | 79,000원 | 입문 | 180분 |
| Vue 3로 시작하는 프론트엔드 | 프론트엔드 | 69,000원 | 입문 | 240분 |
| SQLite와 SQLAlchemy 데이터 모델링 | 데이터베이스 | 59,000원 | 초급 | 150분 |

## 프론트엔드 구성

- 기존 `/` 목록 화면을 강의 카탈로그로 바꾸고 `/courses/{id}` 상세 경로를 추가한다.
- 기존 Vue 3와 수동 history 기반 라우팅 흐름을 따른다. 로그인/회원가입 경로는 유지한다.
- 기존 공통 API 요청 함수의 백엔드 URL 설정, 쿠키 전송, 응답 봉투 해석 및 오류 처리를 재사용한다.
- 강의 카드와 상세 페이지는 반응형으로 구성하고, 이미지가 없거나 로드되지 않을 때 레이아웃이 깨지지 않게 한다.
- 노트 작성 UI는 강의 목록 흐름에서 제거한다. 기존 백엔드 게시판 API는 별도 삭제하지 않는다.

## 검증

- 백엔드 pytest: 강의 목록 응답과 주요 필드, 상세 조회 성공, 존재하지 않는 강의의 404, 테스트 DB에서 시드 중복 방지를 확인한다.
- 프론트엔드 Jest: API 경로와 응답 봉투 해석, 목록 렌더링/상세 이동, 상세 로딩과 조회 실패 상태를 확인한다.
- 전체 기존 백엔드 pytest와 프론트엔드 Jest 스위트를 실행한다.

## 제외 범위와 후속 의존성

- 강사용 강의 상품 작성/수정 및 게시 관리
- 수강생 역할 관리, 수강 신청/보유 강의 관리
- 결제·환불·쿠폰·영수증
- 강의 영상, 목차, 학습 진도
- 외부 이미지 호스팅 및 관리자 페이지

판매 전환을 실제로 처리하려면 이후 결제 및 수강 신청 기능이 필요하다. 이번 조회 화면의 가격 정보는 결제 완료나 구매 가능 상태를 보장하지 않는다.
