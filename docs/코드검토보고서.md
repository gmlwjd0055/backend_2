# 프론트엔드·백엔드 코드 검토 보고서

검토 범위: `frontend/`, `app/`의 인증 흐름과 관련 API 및 설정. 프론트엔드와 백엔드를 각각 독립 검토했으며, 이번 검토 과정에서는 애플리케이션 코드를 수정하지 않았다.

## 요약

인증 흐름에서 우선 조치가 필요한 문제가 확인됐다. 로컬 로그인은 자격 증명을 검증하지 않고 임의 이메일로 토큰을 발급하며, 회원가입은 비밀번호를 평문으로 저장한다. 또한 현재 프론트엔드와 백엔드의 호스트명이 달라 인증 쿠키가 후속 API 요청에 포함되지 않을 수 있고, 프론트엔드는 새로고침 뒤 쿠키 세션을 사용자 상태로 복원하지 않는다.

## 발견 사항

### P1 — 로컬 로그인에서 자격 증명을 검증하지 않음

- 위치: `app/api/routers/user.py:80–96`
- 근거: 로그인 요청으로 받은 이메일과 비밀번호를 그대로 응답 객체에 넣고, 데이터베이스 조회나 비밀번호 비교 없이 요청 이메일로 `EN_AT` 토큰을 발급한다. 따라서 임의 이메일로 로그인해 해당 계정인 것처럼 인증 토큰을 받을 수 있다.
- 추가 영향: `app/api/routers/user.py:82–83`에서 이메일과 비밀번호를 표준 출력에 기록한다.
- 권고: 자격 증명 로그 출력을 제거하고, 등록된 계정을 조회해 저장된 비밀번호 해시와 비교한 뒤 일치할 때만 토큰을 발급한다.

### P1 — 회원가입에서 비밀번호를 평문으로 저장함

- 위치: `app/api/routers/user.py:109–113`
- 근거: 요청 비밀번호를 `User.password`에 그대로 저장한다.
- 권고: 적절한 비밀번호 해시를 저장하고 로그인 검증에도 같은 해시 검증 방식을 적용한다. 기존 평문 레코드가 있다면 안전한 전환 절차가 필요하다.

### P1 — 프론트엔드와 API의 호스트 차이로 인증 쿠키가 전송되지 않을 수 있음

- 위치: `frontend/src/api.js:1–5`, `frontend/vite.config.js:6–9`, `app/api/routers/user.py:71–77, 90–95`
- 근거: 프론트엔드는 기본적으로 `http://127.0.0.1:8000`에 직접 요청한다. Kakao redirect URI는 `http://localhost:5173`이며 Vite 프록시도 `127.0.0.1:8000`을 대상으로 설정돼 있다. `localhost` 페이지에서 `127.0.0.1`로 보내는 요청은 브라우저에서 교차 사이트 요청으로 처리될 수 있지만, 인증 쿠키는 `SameSite=Lax`로 설정돼 있다. 이 경우 로그인 응답 뒤에도 쿠키가 다음 API 호출에 포함되지 않아 인증이 유지되지 않을 수 있다.
- 권고: 개발 환경에서는 프론트와 API의 호스트명을 동일하게 맞추고 Vite 프록시를 사용하도록 API 요청을 상대 경로로 구성한다. 배포 환경에서 사이트 간 쿠키가 필요하다면 HTTPS와 `SameSite=None; Secure`를 함께 적용한다.

### P2 — 새로고침하면 프론트엔드 로그인 상태가 초기화됨

- 위치: `frontend/src/App.vue:16, 70–86, 93–107, 124`
- 근거: 사용자 상태는 메모리의 `user` ref에만 저장된다. 앱 시작 시 `onMounted`는 현재 경로의 데이터만 불러오며, 서버 세션을 조회해 `user`를 복구하지 않는다. Kakao 로그인과 로컬 로그인 모두 성공 직후에는 사용자 이름이 보이지만, 페이지를 새로고침하면 `user`가 다시 `null`이 되어 로그아웃한 것처럼 보인다.
- 권고: 백엔드에 현재 로그인 사용자를 반환하는 세션 조회 API를 두고 앱 시작 때 호출해 사용자 상태를 복원한다.

## 확인 범위와 한계

- 두 에이전트는 코드만 검토했고 수정은 하지 않았다.
- 전체 백엔드 pytest 4개와 프론트엔드 Jest 5개가 통과했다. 현재 테스트는 보고서의 로그인 보안, 쿠키 전달, 새로고침 복원 문제를 재현하거나 검증하지 않으므로, 해당 발견 사항은 코드 경로를 바탕으로 한 검토 결과다.
- 기존에 추가한 CORS 허용 origin 설정은 두 Vue 개발 origin과 쿠키 인증을 허용한다. 다만 CORS 설정만으로는 위의 SameSite 쿠키 문제나 인증 로직 문제가 해결되지 않는다.
